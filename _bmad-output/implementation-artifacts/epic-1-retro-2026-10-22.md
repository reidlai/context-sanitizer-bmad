### 4. Aggregate View: Pattern Divergence & Cross-Story Boundary Review (`bmad-review` Lenses)
- **Checked Scope:** Cross-story interaction between Story 1.2 (`scan_credentials`, `scan_high_entropy_tokens`), Story 1.3 (`scan_and_vault_pii`), and Story 1.4 (`wire/chat.rs`, `wire/completion.rs`), incorporating the 4-lens review pass recorded in `_bmad-output/implementation-artifacts/spec-1-1-to-1-4-epic-1-tier1-guard-vault-wire-ci.md` (lines 98–132).
- **Finding 4.1 — Partial-Token Credential Redaction Can Leave Adjacent Unredacted Substrings inside Standalone High-Entropy Tokens:**
  - **Source:** `context-sanitizer/crates/context-sanitizer/src/guard/mod.rs:15-19` (`run_tier1_guard`), `context-sanitizer/crates/context-sanitizer/src/guard/entropy.rs:131-158` (`scan_high_entropy_tokens`), and `context-sanitizer/crates/context-sanitizer/src/arena.rs:158-166` (`SpanArena::materialize`).
  - **Detail:** In `run_tier1_guard`, `patterns::scan_credentials(arena)` runs before `entropy::scan_high_entropy_tokens(arena)`. In `SpanArena::materialize` (`arena.rs:150-166`), when two `SpanKind::Redacted` spans have equal precedence (`5`), `transform_candidates` sorts by `a.start.cmp(&b.start)` and skips any later span that overlaps an already-accepted span (`candidate.start < existing.end && candidate.end > existing.start`). If an unquoted token has a prefix before a vendor signature (or if a shorter `Redacted` span starts earlier inside a larger high-entropy token), the shorter earlier `Redacted` span wins and the non-overlapping suffix of the larger `Redacted` span is dropped rather than merged.
  - **Disposition:** **Fix now (Remediation Action Item for Epic 2 Story 2.1)** — Merge overlapping `SpanKind::Redacted` intervals in `SpanArena::materialize` (just as `SpanKind::Pruned` intervals are merged at `arena.rs:188-206`) so overlapping credential detections always redact the union of their byte ranges.
- **Finding 4.2 — `ChatCompletionRequest` Tool Schema Definitions (`tools`) Are Passed Through Without Scanning Example/Default Strings:**
  - **Source:** `context-sanitizer/crates/context-sanitizer/src/wire/chat.rs:19-21` and `54-86` (`ChatCompletionRequest::sanitize_in_place`).
  - **Detail:** `sanitize_in_place` sanitizes `messages` (`content`, `tool_calls`, `msg.extra`) and `self.extra`, while leaving `self.tools` untouched so tool schemas are preserved (`FR-10`). This is intentional for Epic 1 (`FR-6` in Epic 2 handles `"tools"` schema minification), but if a developer embeds a secret inside a tool parameter `description` or `default` field, Epic 2 Story 2.3 (`OpenAI JSON Tool Schema Minification`) should ensure Tier 1 guard or schema minification strips/sanitizes description strings.
  - **Disposition:** **Defer to Epic 2 Story 2.3** — Ensure Epic 2 Story 2.3 (`OpenAI JSON Tool Schema Minification`) runs Tier 1 credential redaction over retained string literals or strips `description` fields in `tools`.

  - **Source:** `context-sanitizer/.pre-commit-config.yaml:46-52` vs. `_bmad-output/planning-artifacts/epics.md:124`.
  - **Detail:** Story 1.1 AC states that `pre-push` executes `cargo audit`, unit tests (`cargo test --workspace --lib --bins`), source integration tests (`cargo test --workspace --test '*'`), and `cargo llvm-cov --workspace --all-targets --fail-under-lines 85`. In `.pre-commit-config.yaml:46-52`, `cargo llvm-cov --workspace --all-targets --fail-under-lines 85` compiles and runs all unit and integration targets in a single pass, whereas `.github/workflows/ci.yml:82-91` runs the three commands as separate steps.
  - **Disposition:** **Accept as-is** — Running `cargo llvm-cov --workspace --all-targets --fail-under-lines 85` in local `pre-push` executes all unit and integration tests once instead of compiling and running the test suite twice on every local push, while CI Stage 4 still runs all three steps explicitly.
