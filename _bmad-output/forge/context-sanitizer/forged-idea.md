# Forged Idea: `context-sanitizer` (HARDENED)

## Locked Decisions
- **Tier 3 (`--features ml`) Sequential Off-the-Shelf Pipeline:** Run existing Hugging Face checkpoints sequentially—`SemanticGuard` runs first and short-circuits on threats; `TokenCompressor` (*LLMLingua-2*, Pan et al., ACL Findings 2024, `arXiv:2403.12968`) runs second only on allowed payloads, using $\le 512$-token sentence-aligned chunking for `DeBERTa-v3` and `BERT` checkpoints (and up to 8,192 tokens for `ModernBERT`).
- **Trait-Based Configurable Model Architecture:** Expose `pub trait SemanticGuard` and `pub trait TokenCompressor` with configurable `guard_model_id` and `compression_model_id` (defaulting to `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli` / `MoritzLaurer/deberta-v3-xsmall-zeroshot-v1.1-all-33` built on `microsoft/deberta-v3-base` [He et al., ICLR 2023] + L0 custom terms for `blocked_categories`, and `microsoft/llmlingua-2-bert-base-multilingual-cased-meetingbank` for token pruning) so users can swap in *ModernBERT* (`answerdotai/ModernBERT-base`, Warner et al., 2024), *Llama Prompt Guard 2* (`meta-llama/Llama-Prompt-Guard-2-22M` / `86M`), or custom ONNX/Candle models without code changes.
- **Session-Scoped Shadow Vault + Split Secret Policy:**
  - Generate session-scoped cryptographic tokens (`<SHADOW:EMAIL_8f3a2c>`) tied to a per-session `VaultHandle` with an explicit `.rehydrate()` method on the Rust and Python APIs.
  - **Operational PII** (`EMAIL`, `IP`, `PHONE`, `USER_ID`) uses the Two-Way Shadow Vault for local tool-call rehydration.
  - **Root Credentials** (`AWS_KEY`, `GITHUB_TOKEN`, `PRIVATE_KEY`) default to One-Way Redaction (`[REDACTED_*]`) so indirect prompt injection cannot exfiltrate root keys via tool arguments.
- **100% Pure-Rust Lexical/JSON Scanner & 3-Crate Workspace:**
  - Use a pure-Rust lexical/JSON scanner (`logos` + `serde_json`) to lock code/JSON syntax tokens and detect code injection patterns with zero C/C++ build dependencies.
  - Structure repository as a 3-crate Cargo workspace: `context-sanitizer` (core library), `context-sanitizer-cli` (`context-sanitizer xray` binary), and `context-sanitizer-py` (`PyO3` bindings).
- **Tier 2 (`L0.5`) Zero-Weight Statistical & Submodular Pruning with Tail-Query Auto-Anchoring:** Inspired by *Selective Context* (Li et al., EMNLP 2023) and *RECOMP* (Xu et al., ICLR 2024), use zero-weight static unigram Shannon self-information / IDF ($I(w) = -\log P_{\text{unigram}}(w)$), Okapi BM25 (Robertson & Zaragoza, 2009), and budgeted monotone submodular chunk selection (Lin & Bilmes, ACL 2011). When a single prompt string is passed without an explicit `query`, automatically lock the final user question/instruction as the query anchor.

## Rejected Options & Why
- **Killed: Single Shared-Backbone Multi-Head Checkpoint:** No off-the-shelf Hugging Face model combines *Prompt Guard* / *DeBERTa-v3* `[CLS]` security heads (`SentencePiece` 128k vocab) and *LLMLingua-2* token-pruning heads (`WordPiece` 119k / `XLM-R` 250k vocab) on one shared vocabulary/encoder, and training/distilling custom weights is out of scope.
- **Killed: Global Predictable Shadow Vault IDs (`<SHADOW:EMAIL_1>`) & Rehydrating Root Keys:** Predictable global IDs allow cross-tenant prompt injection leaks, and rehydrating root credentials into tool calls allows exfiltration via indirect prompt injection.
- **Killed: C-Based `tree-sitter` Grammar Dependencies:** Compiling multiple C/C++ language grammars inflates compile times and breaks cross-platform `maturin` wheel builds; pure-Rust lexical scanning achieves structural token locking cleanly.
